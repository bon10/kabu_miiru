# ADR 0002: 配当を売買取引から分離した独立エンティティとする

## Status

Accepted (2026-06-12)

## Context

配当（DIVIDEND）の記録方法として、当初スキーマには 2 つのモデルが併存していた：

- `Transaction.transactionType = DIVIDEND`（売買取引と同一テーブルで扱う）
- `DividendHistory`（配当専用テーブル）

どちらかに一本化する必要があり、ドメインモデルとして配当を売買取引と「同質のもの」として扱うか、「別概念」として扱うかを決める必要があった。

## Decision

配当は `DividendHistory` テーブルにのみ記録する。`Transaction` から `DIVIDEND` 種別は削除し、`Transaction` は売買（BUY / SELL）のみを表すエンティティに限定する。

### 理由

- 売買は投資家が能動的に起こすイベント、配当は会社から受動的に受け取るイベントであり、ライフサイクルが異なる
- 配当固有の属性が存在する：
  - 権利確定日
  - 期末配当 / 中間配当 / 特別配当の区分
  - 1 株あたり配当金（DPS）
- これらを `Transaction` に持たせると、売買レコードで NULL カラムが多発する
- 売買は保有株数を増減させるが、配当は保有株数に影響しないため、不変条件も異なる

## Consequences

- スキーマ：`Transaction.transactionType` から `DIVIDEND` を削除し、BUY / SELL のみとする
- 既存データ：`Transaction(DIVIDEND)` のレコードが存在する場合は `DividendHistory` への移行が必要
- UI：「キャッシュフロー一覧」のように売買と配当を時系列でまとめて表示したい場合は、ビュー層で UNION する
- 集計：年次・半期の配当合計は `DividendHistory` 単独で算出可能

## 決定していないこと

- 「キャッシュフロー一覧」で売買と配当を時系列統合する際の実装方式（ビュー層 UNION）は未決定。曖昧に放置せず、必要になった時点で別途決める
- 配当再投資（DRIP）を保有株数・取得単価へ反映するかは対象外（現状は配当を保有株数に影響しないイベントとして扱う）

## 見直しトリガー

- 配当を売買に紐付けたい要求（DRIP の自動記録、取得原価への算入）が出たとき
- 配当固有属性（権利確定日・DPS・期末/中間/特別の区分）が実質使われず、売買レコードとの差異が無くなったとき

### トリガー検討ログ

- 2026-07-08：`dividendType`（期末/中間/四半期/特別/分配金）を表示専用ラベルとして任意化（NULL 許可）。区分は集計に使われず（集計は支払日基準：ADR 0004）、上記トリガー前半「区分が実質使われない」に該当。ただし後半「売買レコードとの差異が無くなった」は未該当（配当は受動的イベントで保有株数に影響せず、受取通貨・DPS を持つため Transaction とは別概念のまま）。**トリガーは発火せず、DividendHistory 分離の決定は維持**。
- 2026-08-14：受取配当の入力を「1 株あたり配当金（DPS）」に変更し、保存時に保有株数を掛けて総額を確定する実装を追加（[ADR 0007](0007-dividend-receipt-amount-from-per-share.md)）。DPS を**入力として採用したが `DividendHistory` には永続化しない**（総額のみ保存）。トリガー後半「配当固有属性（DPS）が実質使われず、売買レコードとの差異が無くなった」に一部触れるが、配当は依然として受動的イベントで受取通貨を持ち、保有株数に影響しない別概念のまま（Transaction 化はしない）。**トリガーは発火せず、分離の決定は維持**。DPS を列として永続化するか否かは ADR 0007 の見直しトリガーで扱う。
- 2026-09-03：`DividendHistory` に **数量（`shares`）・税額合計（`taxAmount`）・受取金額（`netAmount`）** を追加し、証券会社の配当明細 1 行を写す形にした（[ADR 0015](0015-dividend-statement-fields-and-net-basis.md)）。`shares` を持ったことで `Transaction`（`shares` / `pricePerShare` / `totalAmount`）と**構造の見た目は近づいた**ため、トリガー後半「売買レコードとの差異が無くなった」を改めて検討した。結論は**未該当**：
  - `taxAmount` / `netAmount` / `currency` は `Transaction` に無い配当固有の属性で、**差異はむしろ広がった**
  - `DividendHistory.shares` は**権利確定日の株数**という外から届く確定値で、保有株数を増減させる `Transaction.shares` とは意味が違う。Transaction を直しても再計算されない（ADR 0015）
  - 配当は依然として受動的イベントで、保有株数に影響しない
  **トリガーは発火せず、分離の決定は維持**。なお ADR 0002 が「配当固有の属性」に挙げた**権利確定日は今も列として持っていない**（数量が事実上その代理になっている）。権利確定日そのものを記録する要求が出たら、ADR 0015 の見直しトリガーで扱う。
