# ADR 0007: 受取配当額は登録時の「1株あたり配当金 × 保有株数」で確定し、総額のみ保存する

## Status

Accepted (2026-08-14)

## Context

受取配当（`DividendHistory`）の金額は、これまで**総額を直接入力**して保存していた。しかし証券会社からの配当通知は「**1 株あたり配当金**（DPS）」で届くことが多く、ユーザーが毎回 `DPS × 保有株数` を手計算して総額を入力するのは手間で、桁ミス・株数取り違えも起きやすい。

入力を DPS ベースに変え、保存時に保有株数を掛けて総額を確定する方針にあたり、次を決める必要がある：

- (a) 掛ける保有株数を**どこから・いつの時点で**取るか
- (b) 入力した DPS と受取時の保有株数を**レコードに保存するか**（総額のみにするか）

## 検討した代替案

- **案A（採用）**：入力は DPS。保存（POST）時にサーバー側で**現在の保有株数**（`Stock.sharesHeld`、Transaction 由来の派生キャッシュ：ADR 0003）を掛けて総額を確定し、`DividendHistory` には**総額（`dividendAmount`）のみ**保存する。入力 DPS・受取時株数はレコードに残さない。
- **案B**：従来どおり総額を直接入力する。/ 不採用：証券会社通知は DPS 基準で毎回手計算が要り、今回の要望に反する。
- **案C**：DPS と受取時株数も `DividendHistory` に列として保存し、総額は導出値とする（後から再計算可能）。/ 不採用（現時点）：スキーマ拡張（マイグレーション）が要り今回のスコープ外。ただし「過去値の再計算可能性」（ADR 0003・0005・0006 の思想）とは最も整合するため、見直しトリガーに載せる。
- **案D**：配当を `Transaction`（`shares` / `pricePerShare` を持つ）として記録する。/ 不採用：ADR 0002 で配当は `DividendHistory` に分離済み。差し戻しになる。

## Decision

受取配当の入力値は「**1 株あたり配当金**」とし、受取総額を次で確定する：

```
受取総額 = 1株あたり配当金 × 保有株数（登録時点の Stock.sharesHeld）
```

- 保有株数は**登録（POST）時点**の `Stock.sharesHeld`（Transaction 由来の派生キャッシュ：ADR 0003）をサーバー側で参照する。クライアントが送る株数は使わない（改ざん・陳腐化を避ける）。
- 掛け算は**受取通貨（JPY / USD）建てのまま**行い、総額を受取通貨で保存する。円換算は読み取り時に当日レートで行う（ADR 0006）。
- `DividendHistory` は**総額（`dividendAmount`）のみ**を保持し、入力 DPS・受取時株数は保存しない。
- **保有株数 0 の銘柄は総額を決められないため登録不可**（サーバー・フォーム双方でバリデーションして拒否）。
- 入力フォームは選択銘柄の**保有株数**と**想定受取額**（`DPS × 保有株数`）を表示する。あくまで「想定」で、確定額はサーバー側の登録時保有株数で決まる。

### 理由

- DPS 入力は証券会社通知と一致し、手計算・入力ミスを減らす（本 ADR の主目的）。
- 掛ける株数を `Stock.sharesHeld`（source of truth の射影）から取ることで、保有株数を手更新しない ADR 0003 と整合する。
- 掛け算を受取通貨建てで行い総額を受取通貨で保存するのは、ADR 0006（受取通貨をレコード単位で保持）と整合する。

## 決定していないこと

- **DPS・受取時株数の永続化（案C）は今回見送る。** 将来、受取配当を 1 株単位で分析したい、あるいは保有株数の是正時に総額を再計算したい要求が出たら導入を再検討する。
- **「登録時点」以外の株数**（権利確定日時点・支払日時点の保有株数）を使う選択は今回しない。証券会社準拠の権利確定日ベース保有は、現状データ（米国株は Transaction なし・`purchaseDate: null`：ADR 0005）では復元が難しい。
- **JPY の端数丸め方針**（`DPS × 株数` が小数になる場合）は特に定めず、DB カラム `Decimal(15,2)` の格納に委ねる。

## Consequences

- API `POST /api/dividends` は `dividendAmount` ではなく `dividendPerShare` を受け取り、総額を算出して保存する（[route.ts](../../src/app/api/dividends/route.ts)）。ビジネスルールは [BR-202](../2-domain/business-rules.md)。
- 総額は**登録時点で確定・凍結**される。後で Transaction 再集計により `Stock.sharesHeld` が変わっても、既存の `DividendHistory.dividendAmount` は追従しない（ADR 0003 の「派生値は再計算」思想に対し、受取配当総額は再計算しない確定値であることを許容する）。
- 入力 DPS はレコードに残らないため、「1 株いくらだったか」を `DividendHistory` 単独では復元できない。

### プレモーテム（この決定が誤っていた場合）

- 保有株数を掛けて総額を凍結したため、過去の受取配当を正すには DPS を再入力して登録し直すしかない。DPS を保存していないので、株数だけ是正して総額を再計算する運用ができず、案C への移行コストを後で払うことになる。
- 「登録時点の保有株数」を使うため、支払日と登録日が離れ、その間に売買があると、実際の権利確定日保有株数と食い違う総額を保存しうる。

## 見直しトリガー

- 受取配当を **1 株単位で分析したい**、または**保有株数の是正時に総額を再計算したい**要求が出たとき → DPS・受取時株数を `DividendHistory` に保存する案C への移行を再検討する。
- **権利確定日時点の保有株数**で配当を計算したい要求（証券会社準拠）が出たとき → ADR 0005 が「取得時レート記録＝証券会社準拠」へ動くときと歩調を合わせて再検討する。
- 配当を `Transaction` 化したい要求（DRIP 等）が発火したとき（ADR 0002 の見直しトリガーと連動）。
