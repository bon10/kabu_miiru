# ADR 0006: 受取配当は受取通貨をレコード単位で持つ

## Status

Accepted (2026-07-08)

## Context

受取配当（`DividendHistory`）はこれまで通貨の概念を持たず、`dividendAmount` を常に円建てとみなして集計・表示していた。しかし米国株の配当はドルで入金されることがあり、実例として JEPQ（JPモルガン・ナスダック米国株式・プレミアム・インカム ETF）の配当が 2.30 USD で入金された。従来実装ではこれが「¥2.30」相当として円で保存・合算され、ダッシュボードの `ytdDividendReceived` も未換算のまま合算していた。

ここでの論点は「配当の通貨をどう決めるか」である。ADR 0005 は金額の通貨を**銘柄の市場**（`market === '米国'` ならドル建て）から導出しているが、配当は市場から一意に決まらない。証券会社の**受取方法**が「外貨受取（USD）」か「円受取（証券会社が円転して入金）」かで、同じ米国株でも受取通貨が変わるためである（JEPQ の例は「受取方法: 外貨 / 入金先: 外貨預り金（USドル）」）。

## 検討した代替案

- **案A（採用）：受取通貨を `DividendHistory` にレコード単位の列（`currency`）として持つ。** 集計・表示の直前に当日レートで円換算する（読み取り時換算、ADR 0005 と同じ原則）。
- **案B：銘柄の市場から通貨を導出する（米国株=USD 固定・国内株=JPY 固定）。** スキーマ変更不要で ADR 0005 の `toJpy(market)` に完全準拠できるが、**米国株の円受取を表現できない**。受取方法という配当固有の事実を捨てることになるため不採用。
- **案C：全額を受取時点で円換算して保存する（円で単一保存）。** 元のドル金額が失われ、レート改定や表示単位の切替に耐えられない。ADR 0005 が「ドル建て native 保存＋読み取り時換算」を選んだ理由（過去値を壊さない）と矛盾するため不採用。

## Decision

受取配当は **受取通貨を `DividendHistory.currency`（`JPY` / `USD`、既定 `JPY`）としてレコード単位で保存**し、金額 `dividendAmount` はその受取通貨建てで持つ。集計・表示で円が必要な箇所は、**当日の USD/JPY レートで読み取り時に円換算**する。

- 換算は通貨コードで判定する [toJpyByCurrency](../../src/lib/currency.ts)（`market` で判定する `toJpy` とは別関数）。レート取得は ADR 0005 と同じ [getCurrentUsdJpyRate](../../src/lib/exchange-rate.ts) を共用。
- **金額の表示**：一覧・銘柄詳細では受取通貨のまま表示する [formatMoney](../../src/lib/utils.ts)。USD 受取の行には円換算の目安（`≈ ¥…`）を併記する。
- **集計**：配当サマリ（年計・半期・銘柄別）とダッシュボードの `ytdDividendReceived` は円換算して合算する。
- **通貨の既定値**：入力フォームは選択中銘柄の市場から初期値を提示する（米国株→USD）。ただし証券会社の円受取に備え、ユーザーが手動で変更できる。

### 理由

- 受取方法（外貨／円）という配当固有の事実を保持でき、米国株の円受取も表現できる
- ドル金額を native 保存したまま読み取り時に円換算するため、ADR 0005 の方針と一貫し、過去値を壊さない
- 未指定は `JPY` 既定なので、既存の円建て配当レコード（通貨列導入前）はそのまま円として扱われ、移行不要

## 決定していないこと

- **USD 以外の外貨**（EUR 等）は対象外。`currency` は `JPY` / `USD` の 2 値に限定する（ADR 0005 の「USD 以外を扱うとき見直し」と歩調を合わせる）。
- **入金日レートでの確定換算**は行わない。受取配当も他の金額と同様「当日レート」で読み取り時換算する（為替差益は計上しない）。入金時点のレートを記録・固定する運用は未決。
- 予想配当（`Stock.dividendAmount`、マスタ由来）は本 ADR の対象外。従来どおり ADR 0005 の `toJpy(market)` で円換算する。

## Consequences

- スキーマ：`DividendHistory` に `currency String @default("JPY")` を追加。既存レコードは `JPY` として扱われる。
- 適用箇所：`/api/dividends`（一覧・作成）・`/api/dividends/summary`・`/api/summary`（YTD 受取配当）・銘柄詳細の受取配当履歴。いずれも受取通貨で保持し、円が必要な集計・合算のみ換算する。
- 副次修正：これまで `ytdDividendReceived` はドル配当を未換算で合算していた（潜在バグ）。本 ADR に伴い円換算に修正した。
- パフォーマンス：USD 建て配当が 1 件も無ければレート取得（外部リクエスト）をスキップする。

### プレモーテム（この決定が誤っていた場合）

- 受取通貨をレコードに持たせたことで、入力時に通貨を選び誤ると誤った円換算で集計される。既定値を市場から提示することで誤選択を減らすが、円受取の米国株では手動変更が必要になり、入力負荷・ミスの余地が残る。
- 「当日レート換算」で受取配当を評価するため、実際の入金円貨額（入金日レートで確定した金額）とは一致しない。確定額を正としたい要求が出た場合、入金時レートの記録が必要になり本 ADR を見直すことになる。

## 見直しトリガー

- **入金時点の確定レート（または確定円貨額）を記録したい要求が出たとき** → 「当日レート換算」から「入金日レートで確定換算」への移行を再検討する
- USD 以外の外貨建て配当を扱うとき（現状は `JPY` / `USD` のみ）
- 受取通貨が銘柄の市場から一意に決まる運用に単純化される（円受取を扱わなくなる）とき → レコード単位の `currency` を廃し市場導出（案B）へ戻すことを検討
- ADR 0005 が「証券会社準拠（取得＝購入時レート）」へ移行したとき → 受取配当の換算方針との整合を再確認する
