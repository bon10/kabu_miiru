# ADR 0005: 米国株は当日レートで円換算する（読み取り時換算）

## Status

Accepted (2026-07-04)

## Context

米国株の価格・金額は Yahoo Finance からドル建て（USD）で取得され、`currentPrice` 等にそのまま保存されている。一方で表示・集計はすべて円固定（`formatCurrency` が `JPY`）だったため、次の不具合があった。

- $28 の ETF（例：グローバルX ロボット＆AI・ETF, BOTZ）が「¥28」と表示される
- 米国株の損益がドル値のまま円ラベルで出る
- 日本株（円建て）と米国株（ドル建て）を合算するとダッシュボードの総額で通貨が混在する

円換算方式として、証券会社の口座と同じ「取得＝購入時レート、評価＝当日レート（為替損益込み）」も検討した。しかし既存データの実態は、保有銘柄に対し `Transaction` がごく少数しか無く、**米国株はすべて `purchaseDate: null`・取引履歴なし**（TSV インポート由来）で、取得時のドル円レートを復元できず、為替損益を正しく計算できない。

## Decision

米国株の金額は **当日の USD/JPY レートで円換算する**。換算は保存済みのドル建て値を**表示・集計の直前に換算する（読み取り時換算）**方式とし、DB にはドル建て（native）のまま保持する。

- **単価**（平均取得単価・現在価格）は**建値通貨のまま**表示する（米国株は $、国内株は ¥）。実装：[formatPrice](../../src/lib/utils.ts)
- **金額**（投資額・評価額・評価損益・予想年間配当）は**円換算**して表示・集計する。実装：[toJpy](../../src/lib/currency.ts)
- **為替レート**：Yahoo Finance の `USDJPY=X` を **1 日 1 回**取得し、`ExchangeRate` テーブル（`rateDate` ユニーク）にキャッシュする。実装：[getCurrentUsdJpyRate](../../src/lib/exchange-rate.ts)

### 理由

- 「¥28」問題と通貨混在を最小の変更で解消でき、円ベースで総額が整合する
- 既存データに購入日が無く、取得時レートを前提とする方式は現時点で計算不能
- ドル建て値を保存したままにすることで、単価をドルで見せられ、レート変更にも柔軟（過去値を壊さない）

## Consequences

- **為替損益は損益に含まれない。** 取得原価も評価額も同一の当日レートで換算するため、損益は株価変動のみを反映する（円建ての為替差損益は出ない）
- **将来の拡張**：購入時（または取得時レート）を記録できるようになれば、取得原価だけ購入時レートで換算する「証券会社準拠」方式に移行できる。BUY 時に取得時レートを保存する運用を前提とする
- **適用範囲**：円換算は summary / holdings・by-broker / portfolio(composition・performance・timeline) / stocks(一覧・詳細) の各 API で行う。`Stock` のドル建て値は Read Model（ADR 0003）と同様、表示直前に円へ射影する
- **未対応**：取引履歴ビュー（`transactions-client` / `/api/transactions*`）は本 ADR のスコープ外。米国株の取引レコードがある場合、取引金額はドル値が ¥ 表示のまま残る
- **価格更新**：`/api/prices/update`・バッチはドル建てのまま保存する（変更なし）。円換算は読み取り側で行う

## 見直しトリガー

- **BUY 時に取得時レートを記録できるようになったとき** → 「取得は購入時レート、評価は当日レート」の証券会社準拠方式へ移行を再検討（Consequences「将来の拡張」参照）
- 為替差損益を損益として明示したい要求が出たとき（現状は取得原価・評価額を同一の当日レートで換算し、為替損益は出ない）
- USD 以外の外貨建て銘柄を扱うとき（現状は `USDJPY=X` の 1 通貨のみ対応）
- 1 日 1 回のレート取得粒度では不足する要求（当日約定の厳密な換算等）が出たとき
