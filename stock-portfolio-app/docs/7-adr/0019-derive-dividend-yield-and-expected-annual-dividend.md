# ADR 0019: 配当利回りと予想年間配当は保存せず、1株配当金から読み取り時に計算する

## Status

Accepted (2026-11-11)

## Context

`Stock` は予想配当について 3 つの列を持っていた。

| 列 | 意味 | 値の入り方 |
|---|---|---|
| `dividendPerShare` | 1株配当金（予想） | TSV 取り込み・銘柄編集画面 |
| `dividendYield` | 配当利回り（予想） | TSV 取り込み・銘柄編集画面 |
| `dividendAmount` | 予想年間配当 | TSV 取り込みのみ |

後の 2 つは、ドキュメント上は計算で決まる値である（BR-201：`1株配当金 ÷ 現在価格 × 100`、BR-200：`1株配当金 × 保有株数`）。しかし実装は入力値をそのまま保存しており、次の不具合が出ていた。

- **配当利回りの単位が入力経路で揃っていない。** TSV からはパーセントの値（2.89% なら 2.89）が入り、編集画面は割合（「例: 0.03 (3%)」）を求めていた。表示は割合とみなして 100 倍するため、TSV 由来の銘柄は 289.00% と表示された。2026-11-11 時点で全 68 銘柄のうち 34 銘柄が 1 以上の値で、100 倍で表示されていた
- **現在価格・保有株数の変化に追従しない。** 価格更新や売買のあとも、取り込み時の値のまま残る。銘柄 7347 では保存値 2.89%（取り込み時の株価 761 円で計算した値とみられる）に対し、現在価格 802 円で計算すると 2.74% だった
- **予想年間配当の合計に保有株数 0 の銘柄も入る。** ダッシュボードの「予想年間配当」は全銘柄の保存値の合計で、売り切った銘柄も合計の対象だった

## 検討した代替案

- **案A（採用）：2 列を削除し、API が読み取りのたびに 1株配当金から計算する。** 入力は 1株配当金だけになる。
- **案B：列を残し、価格更新・取引登録のたびに計算して書き戻す。** `profitLoss` などと同じ「派生キャッシュ」（ADR 0003）の扱い。/ 不採用：書き戻す経路（価格更新 2 本・取引登録・TSV 取り込み・銘柄編集）のどれかで漏れると、今回と同じ食い違いが起きる。掛け算と割り算 1 回ずつなので、保存して速くなる場面も無い。
- **案C：列を残して単位だけ揃える（データを 1/100 に直し、入力欄をパーセントにする）。** / 不採用：単位は揃っても、現在価格・保有株数に追従しない問題が残る。

## Decision

**`Stock.dividendYield` と `Stock.dividendAmount` を削除し、API のレスポンスを組み立てるときに計算する。** 実装は [expected-dividend.ts](../../src/lib/expected-dividend.ts)。

- 配当利回り：`dividendYieldOf(1株配当金, 現在価格)`。**パーセントの値**で返す（2.74% なら 2.74）。評価損益率（`profitLossRate`）と単位を揃えるため。現在価格が 0 なら 0
- 予想年間配当：`expectedAnnualDividendOf(1株配当金, 保有株数)`。1株配当金と同じ通貨建て（米国株はドル）で返し、円換算は従来どおり呼び出し側で行う（ADR 0005）
- API のフィールド名（`dividendYield` / `dividendAmount`）は変えない。画面側の変更を表示の単位だけに留めるため
- 銘柄編集画面から配当利回りの入力欄を外す。TSV の「配当利回り」「配当金額」列は列の位置で読む形式のため列としては残し、値は読み飛ばす

マイグレーションは [1_drop_stock_derived_dividend](../../prisma/migrations/1_drop_stock_derived_dividend/migration.sql)。削除する 2 列は計算で置き換わるため、値は移さない。

## 決定していないこと

- **API のフィールド名 `dividendAmount` の改名。** 受取配当の `DividendHistory.dividendAmount`（税引前の実績）と同じ名前で紛らわしい（[ユビキタス言語](../2-domain/ubiquitous-language.md)）。改名すると画面・API 仕様の変更が広がるため、本 ADR では行わない。
- **銘柄一覧などへの配当利回りの表示。** 現状は銘柄詳細だけが表示している。

## Consequences

- 配当利回りは価格更新のたびに、予想年間配当は売買のたびに、何もしなくても最新の値になる。
- ダッシュボードの予想年間配当に、売り切った銘柄が値を持ち込まなくなる（保有株数 0 なので 0 になる）。
- 予想年間配当を「入力した値」として持てなくなる。1株配当金と保有株数から決まらない値（特別配当の見込みなど）を入れたい場合は表現できない。
- 本番 DB へのマイグレーション適用は、**このコードをデプロイしたあと**に行う。先に列を消すと、デプロイ前のコードが消えた列を読もうとして銘柄 API が失敗する。

### プレモーテム（この決定が誤っていた場合）

- 1株配当金がそもそも更新されていなければ、計算結果も古いままになる。保存をやめても、元の値の鮮度はユーザーの入力に依存する。
- 削除した列の値は戻せない。TSV 取り込み時の値を後から参照したくなっても、元の TSV ファイルを探すしかない。

## 見直しトリガー

- **予想配当を外部 API から自動取得するようになったとき** → 1株配当金・配当利回りのどちらを取得し、どちらを計算するかを決め直す
- **銘柄一覧で配当利回りによる並べ替え・絞り込みが必要になったとき** → DB で並べ替えられないため、アプリ側で並べ替えるか、保存に戻すかを検討する
- **1株配当金 × 保有株数 で表せない予想年間配当を扱いたくなったとき** → 予想年間配当の入力値を持つかを検討する
