# ADR 0020: 銘柄の財務指標は Yahoo の通期決算から計算し、MCP からも同じコードで取る

## Status

Accepted (2026-11-12)

## Context

銘柄選びのスキル（value-stock-screener。claude.ai のアカウントに登録し、Claude Desktop・Claude Code から使う）は、ROE・FCF利回り・財務の安全性・200日線・安値圏の基準で銘柄を絞り込む。基準の出典は河村・久保・中川「大規模言語モデルを用いた株式投資戦略の自動生成におけるフィードバック設計」（SIG-FIN-036-31, 2026）で、Claude 系モデルが実装した「王道ファクター」（200日線・ROE・FCF利回り・Z スコア）である。

このあと、本アプリでも保有銘柄が同じ基準を割ったかを判定したい（「買ったときの基準を満たさなくなったら売りを検討する」。論文のルールではなく、論文のファクターを個人の売買に当てはめたもの）。そのとき、スキルとアプリで指標の値が食い違うと、スキルが基準を満たすとして選んだ銘柄が、アプリではすぐ基準割れと表示される。

スキルはこれまで、国内株は松井証券・the-shashi.com、米国株は stockanalysis.com のページを WebFetch で読んでいた。アプリはサーバーからページを読む作りになっておらず、取り先をそろえるにはどちらかを寄せる必要がある。2026-11-12 に次を確認した。

- **Yahoo Finance のページは WebFetch で読めない。** 8058.T の統計ページは ROE・負債比率・52週安値・200日線などがすべて「--」だった（画面を開いたあとに値を読み込む作りとみられる）。貸借対照表のページは数字が読めたが、利益剰余金が無く、単位の表記も食い違っていた
- **Yahoo の fundamentals-timeseries API は、国内株・米国株とも通期の財務の値を返す。** 自己資本・総資産・負債合計・有利子負債・運転資本・利益剰余金・EBIT・売上高・純利益・フリーCF・株式数が取れ、quoteSummary と違って crumb も要らない（8058.T・7203.T・JNJ・TSM で確認）
- **quoteSummary の financialData は期がそろわない。** ROE は直近12か月、フリーCF は別の定義（JNJ で timeseries の通期 193 億ドルに対し 185 億ドル）で、どの期の値かも返らない

## 検討した代替案

- **案A（採用）：アプリに財務の値の取得と指標の計算を置き、MCP サーバーにそれを呼ぶツールを足す。スキルはそのツールを使う。** MCP サーバーはすでにアプリのコード（`src/lib`）を読み込んでいるので、同じ関数を呼ぶだけで値がそろう。
- **案B：スキルは今のページのまま、アプリも同じページを読む。** / 不採用：サーバーから HTML を読む仕組みが新たに要り、ページの作りが変わると壊れる。松井証券は国内株だけ、stockanalysis.com は米国株だけで、取り先が 3 つに増える。
- **案C：スキルが Yahoo のページを WebFetch で読む。** / 不採用：上記のとおり、必要な値の多くが読めない。

## Decision

**財務の値は Yahoo の fundamentals-timeseries API の通期の値を使い、指標の計算とあわせて [fundamentals.ts](../../src/lib/fundamentals.ts) に置く。MCP サーバーに `stock_get_fundamentals` を足し、同じ関数を呼ぶ。**

- **基準期をそろえる：** 自己資本が取れた最新の決算期を基準期とし、各項目は基準期の値だけを使う。基準期の値が無い項目は、古い期の値で埋めずに null とする（JNJ の利益剰余金は最新が 2023 年分で、2025 年の総資産と混ぜると比率が意味を持たない）
- **時価総額は 現在値 × 基準期末の株式数** で出す。毎日の終値に追従させるため、取得時点の時価総額は保存しない。期末より後の自社株買いなどは反映されない
- **財務と株価の通貨が違う銘柄（ADR など）は、時価総額を使う FCF利回りと Altman Z を計算しない。** TSM は財務が台湾ドル、株価がドルで、株式数も ADR の単位と違う
- **自己資本がマイナスなら、ROE と有利子負債倍率を計算しない。** 自社株買いなどで起き（MCD）、割り算の結果が意味を持たないため
- **Altman Z は 1968 年の元の式**（上場製造業向け）で計算する。項目が 1 つでも欠けたら null
- **200日線・年初来安値・52週安値は、chart API の日次終値（2 年ぶん）から計算する。** 場中の安値は含めない。境目は今日ではなく最新の終値の日を基準にする
- 比率はパーセントの値で返す（12% なら 12）。評価損益率・配当利回りと単位を揃える（ADR 0019）
- **MCP サーバーは取った値を保存しない。** DB への接続は ADR 0018 のまま読み取り専用で、外部（Yahoo）への読み取りが増えるだけ

## 決定していないこと

- **アプリでの保存と判定。** 財務の最新値の保存先、価格更新での取り直しの間隔、購入時の値の記録（取引ごと）、基準割れの判定と画面表示は、次の段階で決める。判定は固定の既定しきい値で行い、「買ったあとに基準を割った」と「買ったときから基準に届いていない」を、購入時の値で見分ける方針である
- **銀行・保険・不動産の扱い。** 自己資本比率が低く出る業種で、財務の安全性の基準を割りやすい。判定から外すのではなく、画面に業種の説明を添える方針である

## Consequences

- スキルとアプリが同じ値を見る。スキルの SKILL.md は、指標を `stock_get_fundamentals` で取る形に書き換える
- スキルは kabu-miru（MCP）が使える環境でしか指標を取れない。これまでも保有状況の確認に kabu-miru を使っていたので、使える環境は変わらない
- 国内株もフリーCF・ROE が通期の値になる。これまでスキルが使っていた松井証券の ROE とは一致しないことがある（松井証券の ROE がどの期の値かは確認していない）
- 決算期の直後は、まだ Yahoo に新しい期が載っておらず、1 期前の値で判定することがある

### プレモーテム（この決定が誤っていた場合）

- 非公式 API なので、予告なく形が変わる・止まる。そのとき、スキルの絞り込みとアプリの判定が同時に動かなくなる。価格取得と同じ弱点を、財務の値でも抱える
- 項目の欠けが多い銘柄（米国株の利益剰余金など）では Altman Z が出ず、財務の安全性を有利子負債倍率だけで見ることになる
- 通期の値は決算から最大 1 年古い。業績が急に悪化しても、次の通期決算までは判定に出ない

## 見直しトリガー

- **timeseries API が値を返さなくなったとき** → 公式 API（external-apis.md「公式 API への乗り換え候補」）か、四半期の値への切り替えを検討する
- **通期の値では判定が遅すぎると感じたとき** → 四半期（`quarterly*` / `trailing*`）の値を使うかを決め直す
- **Altman Z が出ない銘柄が多いとき** → 欠けた項目の扱い（1 期前で埋めるか）を決め直す
