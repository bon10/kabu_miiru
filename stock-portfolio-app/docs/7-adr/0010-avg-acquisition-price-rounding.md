# ADR 0010: 平均取得単価は表示時に小数第2位で丸め、投資額は取得原価そのものを表示する

## Status

Accepted (2026-08-16)

## Context

平均取得単価は `取得原価 ÷ 保有株数` で求まる（ADR 0003）。この割り算は割り切れないことがあり、丸めをどこかで挟まざるを得ない。

- 保存側：`Stock.avgAcquisitionPrice` は `Decimal(15,4)`（小数第4位）で、書き込み時点で既に丸められている
- 保存側：`Stock.investmentAmount` は丸めない取得原価そのもの（`Decimal(15,2)`）
- 表示側：`formatPrice` は国内株を整数円で表示するため、平均取得単価が 1,000.6667 でも「￥1,001」になっていた

このため「平均取得単価 × 保有株数」と「投資額」が画面上で一致せず、どちらが正なのかが利用者にも実装者にも読み取れない状態だった。

具体例：1株 @1,000円 と 2株 @1,001円 を買った場合、取得原価は 3,002 円、保有 3 株、平均取得単価は 1,000.6666... 円になる。

## 検討した代替案

- **案A（採用）：取得原価を正とし、平均取得単価は表示のみ小数第2位で丸める**
  - 投資額 = 3,002 円、平均取得単価（表示）= 1,000.67 円。両者は一致しないことを UI に明記する
- **案B：投資額を「丸めた平均取得単価 × 保有株数」で再定義する**
  - 画面上の数字は計算どおり一致するが、投資額が 3,002.01 円となり実際に投じた金額とズレる。損益は `評価額 − 投資額` で出しているため損益にも誤差が乗る。不採用
- **案C：丸めず小数第4位（DB 精度）のまま表示する**
  - 情報欠落は最小だが、国内株で「￥1,000.6667」と桁が多く読みにくい。かつ第4位でも割り切れないケースは残るため、不一致自体は解消しない。不採用

## Decision

**取得原価（`investmentAmount`）を正とし、平均取得単価は表示の直前に小数第2位で四捨五入する。**

- 表示桁数は国内株・米国株とも **小数第2位**。国内株は 1 円未満の端数まで、米国株はセント単位まで見せる。実装：[formatAvgAcquisitionPrice](../../src/lib/utils.ts)
- 現在価格・目標価格に使う `formatPrice` とは分ける。市場から来る値そのものと、割り算の結果である平均取得単価とでは、必要な桁数が異なるため
- 投資額は手数料を含む取得原価そのものを表示する（従来どおり・変更なし）
- **平均取得単価 × 保有株数 が投資額と一致しないこと**を UI に明記する。文言は [AVG_ACQUISITION_PRICE_NOTE](../../src/lib/utils.ts) に集約し、銘柄詳細の投資情報カードと保有一覧テーブルの「平均取得」列で共用する

### 理由

- 取得原価は実際に投じた金額そのもので、損益計算・税務いずれの起点にもなる。表示の都合で丸めた単価から逆算すると、この起点が壊れる
- 丸めは表示層だけに閉じるため、集計・損益計算の精度に影響しない
- 不一致を隠すのではなく注記で明示することで、「どちらが正か」を利用者が判断できる

## 決定していないこと

- **保存精度 `Decimal(15,4)` の妥当性**。今回決めたのは表示桁数のみで、保存側は現状維持とする。表示が小数第2位である限り、保存が第4位でも第6位でも見える結果は変わらない
- **`formatPrice`（現在価格・目標価格）の桁数**。本 ADR のスコープ外で、従来どおり国内株は整数円・米国株はセント単位
- **バッチ価格更新が丸め後の単価で損益を再計算していること**。`calculateProfitLoss` は保存済み（＝小数第4位に丸め済み）の `avgAcquisitionPrice` を使うため、`recalculateStockAggregates` が丸め前の値で出す損益とごく僅かにズレる。実害の観測がないため今回は据え置く

## Consequences

- 国内株の平均取得単価の表示が「￥1,001」から「￥1,000.67」に変わる。整数円だった銘柄も「￥1,250.00」と小数第2位まで桁が揃う
- 平均取得単価を表示する箇所は `formatAvgAcquisitionPrice` を使う。`formatPrice` を使うと桁数が揃わないため、新しい表示箇所を追加するときは注意する
- 注記文言は 1 箇所（`AVG_ACQUISITION_PRICE_NOTE`）に置く。表示場所を増やしても文言が分岐しない

### プレモーテム（この決定が誤っていた場合）

- 単元株しか扱わない国内株では端数が出にくく、「￥1,250.00」の `.00` が常時ノイズになる可能性がある。その場合は「端数があるときだけ小数を出す」表示へ切り替える
- 逆に、小数第2位では足りないほど単価の小さい銘柄（低位株を大量保有、あるいは端株を細かく積み立てるケース）が出ると、丸め後の単価が実態を表さなくなる。桁数の再検討が必要になる

## 見直しトリガー

- 端株・積立で保有株数が小数になる運用を始めたとき（割り算の端数がより頻繁に出る）
- 平均取得単価 × 保有株数 と投資額のズレについて、注記だけでは足りないという指摘が出たとき
- 損益計算の精度に丸めが影響しているという観測が出たとき（「決定していないこと」の3点目が実害になったとき）
- USD 以外の外貨建て銘柄を扱うとき（通貨ごとに適切な小数桁数が異なる）
