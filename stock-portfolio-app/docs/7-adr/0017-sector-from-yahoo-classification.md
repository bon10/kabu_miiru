# ADR 0017: 銘柄のセクターは Yahoo Finance の分類で自動入力し、手入力の値を上書きする

## Status

Accepted (2026-11-09)

## Context

保有を分野別に集計し、まだ投資していない分野を探したい。そのためには、銘柄ごとのセクターが**決まった分類のどれか**に揃っている必要がある。

`Stock.marketSector`（市場・セクター）は自由入力で、値は所有者が思いつきで書いており、正しいかを確かめていない。分類の一覧も決まっていないため、「どの分野を持っていないか」を出せない。銘柄ごとに調べて入力し直すのは手間が大きい。

## 検討した代替案

分類の決め方：

- **案A（採用）：Yahoo Finance の quoteSummary が返す分類（11 種）をそのまま使う。** 日本株も米国株も同じ API から取れる（2026-11-09 に 7203.T・AAPL などで実測）。
- **案B：GICS の 11 セクターを使う。** 国際的に広く使われる分類。/ 不採用：GICS を無料で取得できる経路を見つけられていない。Yahoo の名前を GICS の名前に読み替える案も考えたが、銘柄の振り分けは Yahoo のままなので、名前だけ GICS にしても正確にならない。
- **案C：東証 33 業種を使う。** 日本株には馴染みがある。/ 不採用：米国株には割り当てが無い。
- **案D：分類の一覧を決めて、入力欄を選択式にする。** / 不採用：銘柄ごとに調べて入力する手間が残る。

保存先：

- **案E（採用）：既存の `marketSector` に上書きする。** 手入力の値は正しさを確かめていないので、残す価値が無い。スキーマ変更も要らない。
- **案F：自動入力用の列を別に足し、手入力の値を残す。** / 不採用：残す理由が無い値のためにマイグレーションを増やすことになる。

## Decision

**価格更新（`/api/prices/update`・`/api/batch/price-update`）のついでに、`marketSector` が Yahoo の 11 分類でも「ETF」でもない銘柄だけ、Yahoo から分類を取得して上書きする。** 実装は [updateSectorIfNeeded](../../src/lib/sector.ts)。

- 取得元：`https://query1.finance.yahoo.com/v10/finance/quoteSummary/{symbol}?modules=assetProfile,quoteType`（Cookie と crumb が必要。詳細は [外部API連携仕様](../external-apis.md#セクターの取得)）
- 分類：Basic Materials / Communication Services / Consumer Cyclical / Consumer Defensive / Energy / Financial Services / Healthcare / Industrials / Real Estate / Technology / Utilities（`https://finance.yahoo.com/sectors/` の一覧で確認）
- ETF：Yahoo は ETF に分類を返さないため、`quoteType` が `ETF` の銘柄は「ETF」と保存する
- 既に 11 分類か「ETF」が入っている銘柄は問い合わせない。セクターはめったに変わらないため
- Yahoo から分類が返らなければ、今の値をそのまま残す
- 取得に失敗してもログを残すだけで、価格更新は失敗扱いにしない。セクターが取れないことを理由に、価格を更新できなくしないため

## 決定していないこと

- **保有株数 0 の銘柄の分類。** 価格更新の対象が保有株数 > 0 の銘柄なので、売り切った銘柄には入らない。
- **業種（`industry`）の保存。** Yahoo はセクターより細かい業種（例：Auto Manufacturers）も返すが、保存していない。
- **画面での表示名。** 英語の分類名をそのまま保存・表示している。日本語訳を付けるかは決めていない。
- **入力欄を選択式にするか。** 自由入力のまま。11 分類と「ETF」以外の値を手で入れても、Yahoo が分類を返す銘柄なら次の価格更新で上書きされる。
- **投資信託など、個別株と ETF 以外の扱い。** Yahoo が何を返すかは確認していない。分類が返らなければ手入力の値が残る。

## Consequences

- 導入後の最初の価格更新で、保有銘柄の手入力の値はほぼすべて Yahoo の分類に置き換わる。**元の値は残らない**。
- 最初の価格更新だけ、保有銘柄の数だけ Yahoo への問い合わせが増え、時間が延びる。2 回目以降は、分類が返らない銘柄の分だけになる。関数の実行時間の上限は 300 秒（[ADR 0013](0013-deploy-vercel-tidb.md)）。
- Yahoo が分類を返さない個別株は、価格更新のたびに問い合わせが走る。

### プレモーテム（この決定が誤っていた場合）

- quoteSummary は非公式 API で、crumb の要求も 2026-11-09 時点の実測にすぎない。取得方法が変わるとセクターが埋まらなくなるが、**ログが出るだけで画面には何も出ない**。新しく買った銘柄のセクターが空のままになって初めて気づく。
- 既に分類が入った銘柄は問い合わせないため、Yahoo 側で振り分けが変わっても追従しない。
- Yahoo の分類と GICS では、同じ銘柄でも入る分野が違うことがある。証券会社やニュースが GICS で語る分野と、アプリの集計が一致しないことがある。

## 見直しトリガー

- **quoteSummary から分類が取れなくなったとき**（crumb の取り方が変わった、エンドポイントが無くなった等） → 取得方法を直すか、他の取得元を探す
- **Yahoo の分類の一覧が変わったとき** → `YAHOO_SECTORS` を更新する。古い名前が入った銘柄は、次の価格更新で取り直される
- **GICS など、他の分類と突き合わせる必要が出たとき**、または他の分類を無料で取れる経路が見つかったとき → 案B を再検討する
- **売り切った銘柄の分類も必要になったとき** → 価格更新とは別の取得経路を用意する
