# ADR 0022: 論文の売買ルールを縮めた形で、取得できるデータの範囲でバックテストする

## Status

Accepted (2026-11-13)

## Context

論文「大規模言語モデルを用いた株式投資戦略の自動生成におけるフィードバック設計」（河村・久保・中川、人工知能学会 金融情報学研究会 SIG-FIN-036-31）をもとに、国内株を 5 銘柄に絞って 1 日置きに売買する仕組みを作りたい、という相談があった。実際に金を入れる前に、コストと税を引いた後に損益が残るのかを確かめる必要がある。

論文の売買ルールは 4.2 節にあり、次のとおり。

- 母集団は TOPIX500 のうち TOPIX-17 の銀行・金融・不動産に属する銘柄を除いたもの
- 各日付で、生特徴量ベースの**上位 5%（約 25 銘柄）をロング、下位 5%（約 25 銘柄）をショート**
- **決済は翌営業日の寄り**。建玉は 1 営業日で手じまいし、毎日順位を付け直す
- 取引コストは片道 5bps（0.05%）
- 期間は 2014〜2022 年、特徴量は 80 程度

ここで前提として押さえておくことが 2 つある。

**1. 論文は収益の出る戦略を示した論文ではない。** 主題は「LLM に戦略を改善させるとき、フィードバックの設計が改善プロセスにどう影響するか」であり、結論は「フィードバックの作り方よりモデル選択の方が効く」。表 3 の数値（Claude Sonnet 4.5 で +17.83% など）は**年率の改善幅**であって、リターンそのものではない。図 1 の累積リターンの縦軸は約 −2.0〜+0.5（FXUR）、−1.2〜+0.4（IID）、−1.00〜+0.75（SMDA）で、元の 3 戦略も改善後の戦略も多くがマイナス圏にある。したがって「論文のとおりに作れば儲かる」という前提は置けない。

**2. ADR 0021 との境界。** ADR 0021 は保有銘柄の基準チェックについて「論文の決済ルールを個人の保有に持ち込むものではなく、買ったときの基準を割った銘柄を利用者に知らせるもの」と決めている。本 ADR が決めるのは**売買シグナルのバックテスト**であり、0021 の判定ロジックも決定も変えない。

データ側の制約も分かっている。

- **Yahoo の通期決算は直近 4 期しか返らない。** `fundamentals-timeseries` に `period1` を 2013 年にしても、7203.T で返るのは 2022-03-31〜2025-03-31 期だけだった（2026-11-13 に実測）。ROE・FCF 利回り・自己資本比率・Altman Z を 2014 年まで遡って作ることはできない
- **TOPIX500 の構成銘柄を無料で取れる経路が無い。** 銘柄選びのスキル（value-stock-screener）が TOPIX500 の代わりに東証プライムの大型・中型株を使っているのと同じ問題
- **セクターは Yahoo の quoteSummary でしか取れず、crumb が要る**（ADR 0017。timeseries と違い crumb 無しでは `Invalid Crumb` が返る。2026-11-13 に実測）

## 検討した代替案

- **案A（採用）：論文のルールから、ショート・銘柄数・入れ替え間隔を変えた形で回す。スコアと値段の取得をエンジンから分け、データの制約はスコア側に閉じる。** 取れるデータで今すぐ当たりを見られる。制約が外れたらスコアを差し替えるだけで済む。
- **案B：論文と同じ 2014〜2022 年で王道 4 ファクターを回す。** / 不採用：通期決算が 4 期しか取れないため、2014〜2021 年の ROE・FCF 利回り・自己資本比率を作れない。期末日の決算を全期間に引き伸ばして使えば回るが、それは先読みそのもので、成績が実際より良く出る。
- **案C：J-Quants API など登録や課金が要るデータ源を入れる。** / 不採用：今回の目的は「コストと税を引いて損益が残るかの当たりを見る」こと。その答えが出る前にデータ源を増やす判断はしない。案A でスコアとデータ取得を分けておけば、後から差し替えられる。
- **案D：ユニバースの値段をアプリの DB（本番 TiDB）に入れる。** / 不採用：198 銘柄 × 12 年の日次終値を本番 DB に入れる理由が無い。バックテストは取り直せるファイルで足り、`DailyPrice` は保有銘柄の資産推移のための原資料（ADR 0009）という位置づけを崩さない。

## Decision

**論文の売買ルールから、ショート・銘柄数・入れ替え間隔を変えた形でバックテストする。エンジンは値段とスコアを関数で受け取り、データの形と取得方法を知らない。**

実装は `feature/paper-strategy-backtest` ブランチの `src/lib/backtest/` と `scripts/backtest-*.ts`。アプリのどこからも呼ばないため main には入れていない（「決定していないこと」を参照）。以下に出すファイル名はすべてそのブランチ上のもの。

### 論文から変えたこと

| 項目 | 論文 | 本バックテスト | 理由 |
|---|---|---|---|
| 売り建て | 下位 5% をショート | **無し（買いのみ）** | 相談の要件。信用取引をしない |
| 銘柄数 | 上位 5%（約 25 銘柄） | **固定 5 銘柄**（`positions`） | 相談の要件 |
| 入れ替え | 毎営業日（建玉 1 営業日） | **`holdDays` で選ぶ**。2 で 1 日置き、1 で論文と同じ | 相談の要件は「1 日置き」。論文と同じ間隔も測れるようにして比べる |
| 中立化 | スタイル・セクター中立化 | **無し** | 買い 5 銘柄では中立化できない |
| 母集団 | TOPIX500 ー 銀行・金融・不動産 | **日経 225 ー 銀行・保険・証券・その他金融・不動産**（198 銘柄） | TOPIX500 の構成銘柄が無料で取れない |
| コスト | 片道 5bps | **既定 片道 15bps**（`--cost` で変更） | 5bps は機関投資家の前提。手数料無料でもスプレッドとスリッページが出る |
| 税 | 触れていない | **譲渡益 20.315%**（特定口座・源泉徴収ありと同じく売却のたびに年内通算で精算） | 1 日置きの売買は毎回利益が確定し、含み益での先送りが効かない |
| 単元 | 触れていない | **100 株単位**。枠の予算で 100 株買えなければ建てない | 元手が小さいと枠が埋まらない。その頻度を測る |

論文が示した成績は、この形では一切保証されない。

### 先読みを防ぐ 3 点

バックテストで成績が実際より良く出る原因のうち、構造で防げるものはエンジン側で防ぐ。

1. **順位は建てる前営業日の引けまでの情報だけで作る。** D 日の引け後に順位を付け、D+1 日の寄りで建てる。エンジンは `scoresOn(tradingDays[i - 1])` しか呼ばない
2. **決算は「決算期末日」ではなく「使ってよい日」で引く。** `AnnualFigures.availableFrom` に決算期末日 + 90 日を入れ、`Dataset.annualAsOf` はその日が来た決算しか返さない。timeseries API が返すのは期末日で発表日ではないため、期末日で引くと未公表の数字で売買することになる。国内の上場会社は期末から 3 か月以内に有価証券報告書を出す（決算短信は 45 日前後）ので、短くせず 3 か月を取る
3. **約定は寄り値。** 引け値で順位を付けて同じ日の引け値で約定させない

### 値段は調整済みを使う

`chart` API は `open` / `close` を素のまま、`adjclose` を株式分割と配当で調整した値で返す。素の値のままだと、分割をまたいだ建玉が「株価が半分になった」ように見えて偽の損失になる。`adjclose ÷ close` をその日の調整係数として寄り値にも掛ける（`scripts/backtest-fetch.ts` の `parseAdjustedBars`）。

### スコアは差し替えられるようにする

論文のスコアは LLM が 80 の素特徴量から合成したもので、中身は公表されていない。再現はできないため、2 つを用意して比べる。

| スコア | 中身 | 使える期間 |
|---|---|---|
| `fundamentalScore` | ROE・FCF 利回り・財務の安全性・200 日線乖離を母集団内の順位（0〜1）にして平均。付録 表 A.1 で Claude 4.5 が使った王道ファクターと、スキルの選定基準の組み合わせに合わせた | 通期決算が使えるようになってから（Yahoo が 4 期しか返すため短い） |
| `reversalScore` | 直近 n 営業日のリターンが低い銘柄を上位にする短期リバーサル。値段だけで作れる | 取得した値段の全期間 |

財務の安全性は、スキルの選定基準と同じく自己資本比率（高いほど良い）と有利子負債倍率（低いほど良い）の 2 つで見て、その平均を 1 ファクターとして扱う。指標が 1 つでも欠けている銘柄、自己資本がマイナスの銘柄、まだ使える決算が無い銘柄は候補にしない（スキルが「データなし」の銘柄を落とすのと同じ）。

### 指標の計算を 2 箇所に持つ

バックテストは DB を持たないため、アプリの `computeFundamentalIndicators`（`src/lib/fundamentals.ts`）を呼べない。`fundamentals.ts` は `daily-price.ts` 経由で `prisma.ts` を読み込み、`prisma.ts` はモジュール読み込み時に `PrismaClient` を作るためである。

そこで `src/lib/backtest/indicators.ts` に同じ式を純粋関数として置く。式がずれるとバックテストの基準と基準チェック（ADR 0021）の基準が食い違うため、**両者が同じ値を返すことを `indicators.test.ts` で固定する**。式を変えるときは両方を変え、このテストを通す。

### 期間を 2 つに分けて比べる

- **共通期間**：`fundamentalScore` が枠の数だけ候補を出せる最初の営業日から。4 ファクター（1 日置き / 毎営業日 / 持ち切り）・リバーサル・指数を同じ期間で比べる
- **全期間**：取得した値段の全体。通期決算が要らないリバーサルと指数だけを見る

「持ち切り」（入れ替えなし）を対照に置くのが要点で、**1 日置きの入れ替えそのものが損益に効いているのか、コストを払っているだけなのか**を分けて見るためである。

### 実行の形

`src/lib` に純粋ロジック、`scripts/` に取得と実行を置く。TypeScript のスクリプトを動かすため `tsx` を devDependency に入れた。

```
pnpm backtest:universe   # Wikipedia から母集団を作る（生成物をコミット）
pnpm backtest:fetch      # 値段と決算を backtest-data/ に取る（gitignore 済み）
pnpm backtest:run        # 回して成績を表示し、評価額の推移を CSV に出す
```

## 最初に回した結果

この作りで初めて回した結果を記録する（2026-11-13）。ユニバース 198 銘柄、共通期間は 2022-11-29〜2026-11-13 の 968 営業日。

元手 500 万円・片道 15bps（既定）

| シナリオ | 年率 | 最大DD | 売買回数 | コスト計 | 税計 |
|---|---|---|---|---|---|
| 4ファクター・1日置き | +2.45% | −33.27% | 483 | 4,947,256円 | 185,063円 |
| 4ファクター・毎営業日 | −18.19% | −54.83% | 960 | 5,137,490円 | 0円 |
| **4ファクター・持ち切り** | **+23.66%** | −23.17% | 0 | **5,371円** | 0円 |
| リバーサル・1日置き | −9.50% | −49.95% | 482 | 4,910,404円 | 304,977円 |
| TOPIX ETF 持ち切り | +22.52% | −26.39% | 0 | 7,488円 | 0円 |

元手 500 万円・片道 5bps（論文の前提）

| シナリオ | 年率 | コスト計 |
|---|---|---|
| 4ファクター・1日置き | +20.35% | 2,655,603円 |
| 4ファクター・毎営業日 | +7.55% | 3,876,037円 |
| **4ファクター・持ち切り** | **+23.67%** | 1,790円 |
| TOPIX ETF 持ち切り | +22.54% | 2,498円 |

読み取れること。

1. **入れ替えは損益を増やしていない。** 同じ 5 銘柄を持ち切った場合（+23.66%）より、1 日置きに入れ替えた場合（+2.45%）の方が年率で 21 ポイント低い。論文の前提である片道 5bps にしても、持ち切り（+23.67%）が 1 日置き（+20.35%）を上回る。入れ替えの頻度を上げるほど成績が下がる（毎営業日は 15bps で −18.19%）
2. **払っているコストは元手と同じ規模。** 片道 15bps で 4 年間に 494 万円。元手 500 万円に対してほぼ同額である
3. **1 日置きも毎営業日も、指数（+22.52%）に勝てていない**
4. **元手 100 万円では枠が埋まらない。** 1 枠 20 万円では、2026-11-13 の値段で 198 銘柄のうち 141 銘柄が単元（100 株）を買えない

この結果は見直しトリガーの「『持ち切り』と『1 日置き』の差がコストとほぼ同額だったとき」に当たる。

## 決定していないこと

- **この戦略を実際に売買するか。** 本 ADR はバックテストの作りだけを決める。合格条件（コストと税を引いた後に指数を上回る、最大ドローダウンが許容内など）と、ペーパートレードに進むかは別の判断。
- **アプリへの組み込み。** 画面・API・MCP には出さない。シグナルの日次計算や仮想売買の記録は決めていない。**実装のコードも main に入れていない。** アプリのどこからも呼ばないため、`feature/paper-strategy-backtest` ブランチに置いたままにしてある。回し直す必要が出たらそのブランチを出す。
- **データ源の差し替え。** 通期決算が 4 期しか取れない制約を J-Quants などで外すかは決めていない。外すときは `AnnualFigures` を埋める取得側だけを替える。
- **ユニバースの入れ替え履歴。** 構成銘柄は現在のものだけを持ち、過去の入れ替えを追わない。
- **スコアのしきい値での絞り込み。** スキル（ROE 8% 以上など）のようなしきい値は使わず、順位だけで上位を取る。しきい値を併用するかは決めていない。

## Consequences

- `pnpm backtest:fetch` が Yahoo に 198 銘柄 × 2 エンドポイントを直列で投げる。数分かかるため、画面やバッチの経路からは呼ばない
- `backtest-data/` に数十 MB のファイルが増える（gitignore 済み。取り直せる）
- devDependency が 1 つ増える（`tsx`）。本番のビルドには入らない
- 本番 DB・マイグレーション・デプロイに影響しない。既存の画面と API は触らない
- `src/lib/backtest/universe-jp.json` は生成物だがコミットする（実行のたびに Wikipedia を読まないため）

### プレモーテム（この決定が誤っていた場合）

- **生存者バイアスで成績が良く出る。** ユニバースは現在の日経 225 構成銘柄なので、過去に構成から外れた銘柄（多くは成績が悪くて外れた）が入っていない。「指数を上回る」という結果が出ても、この分を割り引く必要がある
- **日経 225 は TOPIX500 の代わりにならない。** 225 銘柄しかなく、選び方も時価総額順ではない。論文の母集団（約 475 銘柄）より狭く、1 日置きの入れ替えで同じ銘柄が選ばれ続けやすい
- **通期決算しか無いため、4 ファクターのスコアは年に 1 回しか大きく動かない。** 株価で動くのは FCF 利回り・Altman Z・200 日線乖離だけ。順位がほとんど変わらないなら、1 日置きの入れ替えは同じ 5 銘柄を売って買い直すだけになり、コストと税を払うだけになる。これは「持ち切り」との比較で表に出る
- **`indicators.ts` と `fundamentals.ts` がずれる。** テストで止めているが、テストごと直してしまえば通る。ADR 0021 のプレモーテム（スキルとコードのしきい値がずれる）と同じ構図
- **availableFrom の 90 日が実態と合わない。** 実際の発表日より遅く置いているので先読みにはならないが、決算直後の 1〜2 か月は古い期の数字で判断している。成績は実際より悪く出る方向
- **Yahoo の非公式 API が壊れる。** 公式ドキュメントが無く、crumb の要否もエンドポイントごとに違う（ADR 0020 と同じリスク）

## 見直しトリガー

- **`fundamentals.ts` の指標の式を変えたとき** → `indicators.ts` を合わせ、`indicators.test.ts` を通す
- **スキル（value-stock-screener）の選定基準を変えたとき** → `fundamentalScore` の組み合わせを合わせるか、合わせない理由を書く
- ~~**「持ち切り」と「1 日置き」の差がコストとほぼ同額だったとき**~~ → **2026-11-13 に該当した**（「最初に回した結果」）。王道 4 ファクターは通期決算しか動かないため順位が日次で変わらず、1 日置きの入れ替えはコストを払うだけになっている。1 日置きを続けるなら、順位が日次で動くスコアが要る
- **通期決算より細かい財務（四半期）か、過去に遡れるデータ源が手に入ったとき** → 案C を見直し、論文と同じ 2014〜2022 年で回す
- **バックテストの結果を受けてペーパートレードに進むとき** → 仮想売買の記録をアプリに持つかを決める（本 ADR の「決定していないこと」）
- **ユニバースを TOPIX500 に替えられる経路が見つかったとき** → 生存者バイアスと母集団の狭さを見直す
