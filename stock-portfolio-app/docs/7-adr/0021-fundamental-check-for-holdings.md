# ADR 0021: 保有銘柄の基準チェックは、固定の基準と購入時の指標で判定する

## Status

Accepted (2026-11-12)

## Context

銘柄選びのスキル（value-stock-screener）は、ROE・FCF利回り・財務の安全性・200日線の基準で銘柄を選ぶ（ADR 0020）。買ったあとも、その銘柄が基準を満たし続けているかを、日次〜月次で確かめたい。考え方は「買ったときの基準を満たさなくなったら売りを検討する」で、論文（SIG-FIN-036-31）のルールではなく、論文のファクターを個人の売買に当てはめたものである。

論文が決めている売りは、銘柄の良し悪しではなく日付で決まる。4.2 節の取引条件は「決済タイミングは翌営業日の寄り」「各日付においてユニバース内から生特徴量ベースで上位 5% 以内をロング（買い）、下位 5% 以内をショート（売り）」で、建玉は 1 営業日で決済し、毎日順位を付け直す。利確・損切・保有期間のルールは論文に無い。本アプリの判定が使う指標のうち ROE・FCF利回り・200日線・Z スコアは、付録の表 A.1 で Claude 4.5 が作った実装の特徴として挙げられているもので、しきい値も売却の条件も論文には書かれていない。したがって本アプリの判定は、論文の決済ルールを個人の保有に持ち込むものではなく、買ったときの基準を割った銘柄を利用者に知らせるものである。

判定に要る値を、次の観点で分けた。

- **判断時の値だけで足りるもの**：「今の値がしきい値を割ったか」は、今の値としきい値だけで判定できる
- **購入時と比べたいもの**：スキルは候補が残らないと条件を緩めて選ぶ（ROE 8% → 7% など）。緩めて買った銘柄は、固定のしきい値で見ると買った直後から基準を割っている。これを「買ったあとに悪くなった」と区別するには、購入時の値が要る
- **後から取り直せないもの**：購入時の FCF利回りや Altman Z は、そのときの株価で決まる。財務の値も Yahoo からは最新期しか取らない（ADR 0020）。購入時に残さないと失われる

利用者は投資の専門家ではなく、しきい値を自分で決めて入力するのは難しい。

## 検討した代替案

- **案A（採用）：しきい値は固定（スキルの初期値）。購入時の指標を取引ごとに残し、「基準割れ」と「購入時から未達」を見分ける。** 入力は要らない。
- **案B：購入時に使ったしきい値を取引ごとに入力・保存する。** / 不採用：利用者が何を入れればよいか分からない。スキルが緩めた値をアプリに渡す経路も無い。
- **案C：今の値だけで判定し、購入時の値は持たない。** / 不採用：条件を緩めて買った銘柄が、買った直後から「基準割れ」と出続ける。後から比べたくなっても値が残っていない。

## Decision

**しきい値は固定で、スキルの初期値と同じにする。財務の最新値を銘柄ごとに、購入時の指標を買いの取引ごとに保存し、判定は読み取りのたびに計算する。** 判定は [fundamental-check.ts](../../src/lib/fundamental-check.ts)、保存と読み出しは [fundamental-store.ts](../../src/lib/fundamental-store.ts)。

### 判定

| 項目 | 国内株 | 米国株 |
|---|---|---|
| ROE | 8%以上 | 8%以上 |
| FCF利回り | 3%以上 | 3%以上 |
| 財務の安全性 | 自己資本比率 40%以上、有利子負債倍率 100%以下 | Altman Z 1.8以上（今の値が無ければ有利子負債倍率 100%以下） |
| 200日線 | 現在値が上回る | 現在値が上回る |

- 項目ごとに「満たしている」「基準割れ（購入時は満たしていて、今は下回る）」「購入時から未達」「データなし」を出す。購入時の値が無ければ、今下回っている項目は基準割れとする
- 銘柄の判定は、基準割れが 1 つでもあれば基準割れ、無くて購入時から未達があれば購入時から未達、それ以外は満たしている
- 購入時の値は、その銘柄の**最新の**購入時の指標を使う。売りは銘柄単位で考えるため、直近の買いのときと比べる
- 安値圏（スキルの条件）は買うタイミングの条件なので見ない。ETF は財務の値が無いので判定しない
- 自己資本がマイナスの銘柄は、ROE と有利子負債倍率を「満たさない」とみなす（スキルでも落とす）
- 銀行・保険・証券（Financial Services）と不動産（Real Estate）は、事業の性質で財務の安全性の基準を割りやすい。判定から外さず、画面と MCP に業種の説明を添える

### 保存

- **財務の最新値（`StockFundamental`）**：通期決算の値をそのまま持つ。指標は保存せず、判定のたびに `Stock.currentPrice` で計算する（FCF利回りと Altman Z が株価で変わるため。ADR 0019 と同じ考え方）。価格更新のついでに、無いか取得から 30 日以上経っていれば取り直す。失敗しても価格更新は失敗扱いにしない（セクターと同じ。ADR 0017）
- **購入時の指標（`FundamentalSnapshot`）**：計算済みの指標を持ち、あとから変えない。FCF利回りなどは取引の単価で計算する。買いの取引の登録直後に作り、Yahoo から取れなかった分は次の価格更新で作り直す。初期残高（ADR 0008）は実際の購入ではないので作らない
- **チェック開始日**：基準チェックを始めた日。`POST /api/batch/fundamental-check-start` を初めて `apply` で実行した日を `Setting` に保存し、その時点の保有（ETF を除く）に 1 件ずつ購入時の指標を作る（`isCheckStart = true`）。チェック開始日より前の取引には個別に作らない。値はチェック開始日のもので、実際の購入時の値ではないことを画面に添える
- **200日線**は日次終値（`DailyPrice`）から計算する。新しく買った銘柄は日次終値が足りないため、購入時の指標を作るときに Yahoo から取った 2 年ぶんの終値を `DailyPrice` に保存する（既存の値は上書きしない。保有前の日の終値は、資産推移の計算では株数 0 を掛けるので結果に影響しない）

### 読み出し

- 画面：`GET /api/fundamental-checks`（`stockId` で 1 銘柄）。銘柄詳細に「基準チェック」の欄、保有一覧に件数の要約バーと、基準割れ・すべて満たしているの銘柄に付く印、基準チェック一覧（`/fundamental-checks`）に判定ごとの件数と、基準に届いていない銘柄・すべて満たしている銘柄の一覧を出す。購入時から未達の銘柄に行ごとの印を出さない理由と、画面に出すラベル・文言は[基準チェックの画面要件](../1-requirements/fundamental-check.md)
- MCP：`portfolio_check_fundamentals`。同じ `loadFundamentalChecks` を呼ぶ。DB を読むだけで Yahoo には問い合わせない。読み取り専用ユーザーに `StockFundamental`・`FundamentalSnapshot`・`DailyPrice` の SELECT 権限を足す（ADR 0018 の見直しトリガー「MCP が読むテーブルを増やすとき」）

## 決定していないこと

- **基準割れの通知。** 画面と MCP で見るだけで、メールなどで知らせる仕組みは無い。
- **取引を編集したときの購入時の指標。** 取引の単価を直しても、購入時の指標は作り直さない（取引を消すと一緒に消える）。
- **しきい値の変更。** スキルの初期値を変えたら、`fundamental-check.ts` も合わせて変える必要がある。設定画面からは変えられない。

## Consequences

- 価格更新のたびに、銘柄ごとに財務の最新値と購入時の指標の有無を確かめる DB の読み取りが増える。Yahoo への問い合わせは、取り直しが要る銘柄（30 日に 1 回）と購入時の指標が無い取引のぶんだけ増える
- 買いの取引の登録が、Yahoo への問い合わせ 2 回ぶん遅くなる
- 本番 DB にマイグレーション（[2_add_fundamental_check](../../prisma/migrations/2_add_fundamental_check/migration.sql)）を当てる必要がある。テーブルを足すだけなので、コードのデプロイの前後どちらでもよい
- 運用の手順：マイグレーションを当て、デプロイし、チェック開始のバッチを dry-run → apply の順に実行する。MCP の読み取り専用ユーザーに権限を足す

### プレモーテム（この決定が誤っていた場合）

- しきい値はスキルの初期値をコードに写したもので、スキル（claude.ai に登録した SKILL.md）を変えても自動では追従しない。食い違うと、スキルで選んだ銘柄がアプリでは基準割れになる
- 通期決算の値なので、業績の悪化が判定に出るのは次の通期決算が Yahoo に載ってから。急な悪化には気づけない
- チェック開始日に作った購入時の指標は「その日の値」なので、チェック開始日より前に買った銘柄では、買ったあとの悪化を見逃す（チェック開始日の時点で既に下回っていれば「購入時から未達」になる）

## 見直しトリガー

- **スキルの選定基準を変えたとき** → `fundamental-check.ts` のしきい値を合わせる
- **基準割れを見落とすことが増えたとき** → 通知、または四半期の値（ADR 0020 の見直しトリガー）を検討する
- **取引の編集をよく使うようになったとき** → 編集時に購入時の指標を作り直すかを決める
