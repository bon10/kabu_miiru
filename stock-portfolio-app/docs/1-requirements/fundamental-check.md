# 基準チェックの画面要件

## 機能概要

保有銘柄の稼ぐ力と財務が悪くなっていないかを、所有者が画面で確かめる機能。

判定のしきい値・計算・保存は [ADR 0023](../7-adr/0023-buy-sell-timing.md)・[ADR 0021](../7-adr/0021-fundamental-check-for-holdings.md) と [sell-signal.ts](../../src/lib/sell-signal.ts) / [fundamental-check.ts](../../src/lib/fundamental-check.ts) が決める。**この文書は、その判定を画面でどう見せるか（どの画面に何を出すか、どの言葉で書くか）を決める。** 判定の中身は扱わない。

所有者は投資の専門家ではないため、判定の名前だけを出さず、**その判定が何を意味するか**と**次にすること**を同じ場所に書く。

## 銘柄の判定はひとつ

**画面に出す銘柄の判定は、売りの判定（`SellStatus`）だけ。**

以前は購入時の指標と比べる判定（「見直し対象」「購入時から未達」）も銘柄の判定として出していたが、やめた。判定が 2 つあると、食い違ったときにどちらに従えばよいか分からなくなる。実際に TSM で、株価が 200日線を 1.1% 下回っただけで「見直し対象・持ち続けるか考えるきっかけ」と出た一方、売りの判定は「引き金なし」だった（2026-11-14）。

購入時の値は**比べるための数字**として項目の表に残す。判定には使わない。

## 判定ごとに画面に出す言葉

判定の値（`SellStatus`）ごとに、ラベルと一文を [fundamental-check-card.tsx](../../src/components/stocks/fundamental-check-card.tsx) の `SELL_STATUS_LABEL` / `SELL_STATUS_SUMMARY` に持つ。3 つの画面と MCP で同じ言葉を使う。

| 判定 | 画面のラベル | 画面に出す一文 |
| --- | --- | --- |
| `consider_sell` | 売りを検討 | 稼ぐ力か財務の安全性が、前の年より悪くなって基準を下回った状態が 2 期続いています。この銘柄を持ち続けるか、もう一度考えるきっかけです。 |
| `first_period` | 1 期目 | 稼ぐ力か財務の安全性が、前の年より悪くなって基準を下回りました。1 期目なので、次の決算でも戻らなければ考えるきっかけになります。今すぐすることはありません。 |
| `ok` | 引き金なし | 売りを考える材料はありません。基準を下回っている項目があっても、前の年より良くなっているなら引き金になりません。今はすることはありません。 |
| `no_data` | 判定できない | 比べる前の年の決算がまだありません。ヘッダーの「価格更新」を押すと通期決算を取りに行きます。 |
| `not_applicable` | 対象外 | ETF は財務の値が無いため、売りの判定の対象外です。 |

## 項目ごとに出す 2 種類の表

項目の表は 2 つあり、**役割が違う**。混ざらないよう、見出しと列で区別する。

### 1. 参考の数字（`FundamentalValueItem`）

項目ごとの今の値・購入時の値と、**今その値が基準を満たすか**を出す。銘柄をどうするかは書かない。

| 列 | 中身 |
| --- | --- |
| 項目 | 項目名と 1 文の説明。売りの判定に使わない項目には「売りの判定に使わない」と添える |
| 基準 | しきい値（「8%以上」など） |
| 今 | 今の値 |
| 購入時 | 購入時（またはチェック開始日）の値。比べるための数字 |
| 今の状態 | 満たしている / 満たしていない / データなし |

**「満たしていない」に次にすることを書かない。** 行動は銘柄の判定（売りの判定）だけが示す。

### 2. 売りの判定の内訳（`SellItem`）

引き金が付いた銘柄（`consider_sell` / `first_period`）にだけ出す。引き金が無い銘柄に出すと、見るものが増えるだけで判断が変わらない。

| 列 | 中身 |
| --- | --- |
| 項目 | ROE・自己資本比率・有利子負債倍率（米国株は ROE・有利子負債倍率） |
| 基準 | しきい値 |
| 直近期 | 直近の通期決算の値 |
| 前の期 | その 1 つ前の通期決算の値 |
| 判定 | 引き金なし / 1 期目 / 2 期続いている / データなし |
| 1 期目 | 1 期目と判定した決算期末日 |

## 項目ごとの説明

数字の意味が分からないと次の行動を決められないため、項目名のとなりに 1 文の説明を出す。文言は [utils.ts](../../src/lib/utils.ts) の `FUNDAMENTAL_CRITERION_HINT` に持つ。しきい値はここには書かない（基準の列で出す）。

| 項目 | 画面に出す説明 |
| --- | --- |
| ROE | 集めたお金でどれだけ稼げているか。低いほど稼ぐ力が弱いという見方です。 |
| FCF利回り | 手元に残る現金が、株価に対してどれだけあるか。マイナスは現金が出ていっている状態です。 |
| 自己資本比率 | 借金に頼らず自分のお金で事業をしているか。高いほど倒れにくいという見方です。 |
| 有利子負債倍率 | 利息の付く借金が自分のお金より多くないか。100% を超えると借金のほうが多い状態です。 |
| Altman Z | 倒産しにくさの目安。低いほど危ないという見方です（米国株で使います）。 |
| 200日線 | ここ 200 日の平均の株価より、今が上か下か。下なら下がり気味ということです。 |

## 判定を出す 3 つの画面

| 画面 | 出すもの | 読み出し |
| --- | --- | --- |
| 基準チェック一覧（`/fundamental-checks`） | 判定ごとの件数、引き金が付いた銘柄の一覧、引き金が無い銘柄の一覧 | `GET /api/fundamental-checks` |
| 保有一覧（`/holdings`） | 件数の要約バーだけ | `GET /api/fundamental-checks` |
| 銘柄詳細（`/stocks/[id]`） | その銘柄 1 件の 2 種類の表 | `GET /api/fundamental-checks?stockId=` |

### 基準チェック一覧

[fundamental-checks-client.tsx](../../src/components/stocks/fundamental-checks-client.tsx)。上から次の順に出す。

1. **判定ごとの件数**（売りを検討・1 期目・引き金なし・対象外の 4 つ）。売りを検討だけ色を付け、ほかは同じ見た目にする。枠ごとに「所有者がすること」を 1 文添える。`no_data` が 1 件以上あるときだけ、件数を枠の下に文で出す
2. **引き金が付いた銘柄の表**。1 行 1 銘柄で、丸い印・銘柄名（銘柄詳細へのリンク）・コード・市場・判定・悪くなった項目（項目名と「直近期 ← 前の期」）・1 期目の決算期末日を出す
3. **引き金が無い銘柄の表**。1 行 1 銘柄で、丸い印・銘柄名（銘柄詳細へのリンク）・コード・市場・セクターを銘柄名順に出す。件数だけでは「どの銘柄が落ち着いているのか」が分からないため、名前を出す。1 件も無いときは表そのものを出さない
4. **注記**。該当する銘柄があるときだけ業種の注記（銀行・保険・証券、不動産）を出し、通期決算と判定に使わない項目の注意は常に出す

**対象外（ETF）と判定できない銘柄は件数だけ出し、どちらの表にも出さない。**

並び順は、売りを検討を先に、次に引き金の数が多い順、同数なら銘柄名順。

絞り込みは、引き金になっている項目で行う。ボタンは「すべて」と、引き金が付いた銘柄が 1 件以上ある項目だけを、銘柄数の多い順に並べる（[countTriggeredItems](../../src/lib/fundamental-check-summary.ts)）。市場で項目が違う（国内株は自己資本比率も見る）ため、ボタンは判定結果に入っている項目から作る。

### 保有一覧

[holdings-client.tsx](../../src/components/holdings/holdings-client.tsx)。見出しと合計の枠の間に要約バーを出し、売りを検討・1 期目・引き金なしの件数と、基準チェック一覧へのリンクを並べる。基準チェックが 1 件も読めなかったときはバーを出さない。

**行ごとの印とバッジは出さない。** 売りを検討と引き金なしで保有の大半を占めるため（2026-11-14 時点では 51 銘柄のうち 42 銘柄）、行ごとに印を出すと一覧の大半に印が並び、価格更新失敗のバッジなど他の印が埋もれる。どの銘柄かは基準チェック一覧で見る。

### 銘柄詳細

[fundamental-check-card.tsx](../../src/components/stocks/fundamental-check-card.tsx) の「基準チェック」欄。見出しの横に判定のラベル、その下に一文、続いて参考の数字の表、引き金が付いていれば売りの判定の内訳の表を出す。表の下に、業種の注記、購入時の値の日付（チェック開始日の値ならその説明と「判定には使わない」）、財務の値の期末と取得日時、価格の最終更新日時を出す。

## 丸い印（基準チェック一覧）

基準チェック一覧の表で、銘柄名の前に出す。実装は `FundamentalStatusIcon`（[fundamental-check-card.tsx](../../src/components/stocks/fundamental-check-card.tsx)）。

| 判定 | 丸い印 |
| --- | --- |
| 引き金なし | 青い丸（`CircleCheck`） |
| 売りを検討 | オレンジの丸（`CircleAlert`） |
| 1 期目・判定できない・対象外 | 出さない（表の判定の列に文字で出る） |

**印は銘柄名の前に置き、印が無い銘柄も同じ幅を空ける。** 印の有無で銘柄名の開始位置がずれると、名前を縦に読めなくなるため。幅の予約は `FundamentalStatusIcon` が自分で行う。

**丸い印はツールチップで意味と次にすることを出す。** 色と形だけで意味を伝えないため。実装は Radix の Tooltip（[ui/tooltip.tsx](../../src/components/ui/tooltip.tsx)）で、`title` 属性は使わない。`title` はブラウザが出す素の吹き出しで、出るまで時間がかかり、見た目を揃えられず、キーボードでは出ないため。印はボタンにしてフォーカスを当てられるようにし、読み上げ用の文も持たせる。

**引き金なしの印を緑にしない。** 同じ行に評価損益のプラスを緑で出している画面があるため、緑だと株価が上がっていることと見分けられなくなる。

## 画面に出さないこと

- **売買の指示。** 売りを検討は「売ってよい」ではなく、持ち続けるかを考え直すきっかけとして書く。どの画面にも「売買を勧めるものではありません」を添える
- **2 つめの銘柄の判定。** 購入時と比べる判定は銘柄の判定として出さない（上の「銘柄の判定はひとつ」）
- **しきい値の変更。** 基準は固定で、設定画面からは変えられない（ADR 0021）
- **通知。** 売りを検討が出たことをメールなどで知らせる仕組みは無い（ADR 0023 の「決定していないこと」）
- **安値圏の判定。** 買うタイミングの条件なので、保有銘柄の判定では見ない（ADR 0023）
