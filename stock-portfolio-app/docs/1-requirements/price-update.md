# 株価自動取得機能要件

## 機能概要

保有株式の現在値を取得し、損益計算を最新化する機能。現在値は所有者が画面のボタンで更新する。

## 実行タイミング

**現在価格は定期実行しない。** 所有者がアプリを開いたときに、ヘッダーの「価格更新」ボタンを押して更新する。今の使い方では自動更新が要らないため（ADR 0013）。必要になったら `/api/batch/price-update` を Vercel Cron で 1 日 1 回呼ぶ形で足す。

- **対象銘柄**: 保有株数 > 0 の銘柄のみ

### ボタンによる更新

価格更新は、**画面の「価格更新」ボタンを押したときだけ**実行される。保有一覧や銘柄詳細を開いただけでは実行されない。ボタンは 3 か所にあり、いずれも `POST /api/prices/update`（[requestPriceUpdate](../../src/lib/price-update.ts)）を呼ぶ。

| ボタンの場所 | 更新される銘柄 |
| --- | --- |
| ヘッダー（[header.tsx](../../src/components/layout/header.tsx)） | 保有株数 > 0 の全銘柄 |
| 保有一覧の各行（[holdings-client.tsx](../../src/components/holdings/holdings-client.tsx)） | その行の銘柄 |
| 銘柄詳細（[stocks/[id]/page.tsx](../../src/app/stocks/[id]/page.tsx)） | その銘柄。保有株数 0 の銘柄ではボタンを押せない |

画面を介さずに全銘柄を更新するときは、`POST /api/batch/price-update`（`X-API-Key`）を呼ぶ。Vercel Cron が毎日呼んでいるのは日次終値の取り込み（`/api/batch/daily-close`）だけで、現在価格の更新は定期実行されていない（ADR 0013）。

### 価格更新をしないと変わらない数値

現在価格は表示のたびに Yahoo から取得しているのではなく、`Stock` テーブルに保存した値を出している。そのため、次の数値は価格更新をしないと変わらない。

| 数値 | 持ち方 | 価格更新以外で変わるとき |
| --- | --- | --- |
| 現在価格 | `Stock.currentPrice` に保存 | なし |
| 評価額 | 保存しない。表示のたびに「保有株数 × 現在価格」で計算する | 取引の登録・編集で保有株数が変わったとき |
| 評価損益・評価損益率 | `Stock.profitLoss` / `Stock.profitLossRate` に保存 | 取引の登録・編集のとき（保存済みの現在価格で計算し直す） |
| セクター | `Stock.marketSector` に保存。空か Yahoo の分類以外が入っている銘柄だけ価格更新で埋める（FR-046） | なし（画面からは入力できない） |
| 「価格更新失敗」のバッジ | `Stock.priceUpdateStatus` に保存 | なし |

計算式を直しても、DB に保存済みの評価損益・評価損益率は古い式の値のまま残る。価格更新を押すと、保有中の銘柄は新しい式で保存し直される。

**例外：米国株の円の金額。** 米国株はドル建てで保存し、表示のたびにその日（JST）の USD/JPY レートで円に換算する（ADR 0005）。レートはその日の分が DB に無ければ Yahoo から取得して保存し、あればそれを使う（[getCurrentUsdJpyRate](../../src/lib/exchange-rate.ts)）。そのため価格更新をしなくても、日が変わってレートが動けば、米国株の評価額・評価損益の**円の数字**は変わる。ドル建ての現在価格と評価損益率は変わらない。

**価格更新と関係ないもの。** 資産推移のグラフは、毎朝の cron が取り込む日次終値から表示のたびに組み立てる（ADR 0009）。価格更新を押さなくても日々進む。

## データソース戦略

### メインAPI: Yahoo Finance

- **エンドポイント**: `https://query1.finance.yahoo.com/v8/finance/chart/{symbol}`
- **対象**: 日本株（.T付きコード）、米国株
- **認証**: APIキー不要（非公式API）
- **レスポンス時間**: 通常1-2秒
- **制限**: 1分間に100リクエスト（仕様値）
- **データ精度**: リアルタイム（15分遅延の場合あり）

#### APIレスポンス形式

```json
{
  "chart": {
    "result": [
      {
        "meta": {
          "regularMarketPrice": 150.25,
          "previousClose": 148.5,
          "regularMarketChange": 1.75,
          "regularMarketChangePercent": 1.18
        }
      }
    ]
  }
}
```

#### 銘柄コード変換

- **日本株**: 数字コード（例：7203）→ API呼び出し用コード（7203.T）
- **米国株**: ティッカーシンボル（例：AAPL）→ そのまま使用

### 補完API: 楽天RSS（将来実装）

- **対象**: 地方証券所銘柄（名証、福証等）
- **用途**: Yahoo Financeで取得できない銘柄の補完
- **制限**: 要調査

### フォールバック: モックデータ生成

- **用途**: API取得失敗時の代替手段
- **対象**: 開発環境での動作確認
- **ログ**: 手動更新履歴の記録

## 機能要件

### FR-040: 自動価格更新バッチ

- **説明**: 定時実行での価格一括更新
- **実行環境**: サーバーサイドバッチ処理
- **ログ出力**: 実行結果の詳細ログ
- **エラー処理**: 個別銘柄のエラーは全体を停止させない
- **実装状況**: 見送り。バッチ（`POST /api/batch/price-update`）はあるが定期実行していない（ADR 0013）

### FR-041: 手動価格更新

- **説明**: ユーザー操作による即座の価格更新
- **対象選択**: 全銘柄または特定銘柄
- **進捗表示**: リアルタイムの更新進捗表示
- **結果表示**: 更新成功・失敗の詳細結果
- **実装状況**: 基本機能実装済み

### FR-042: 価格履歴保存

- **説明**: 取得した価格データの履歴保存
- **保存間隔**: 取得毎に記録
- **データ項目**: 価格、取得日時、データソース、市場セッション
- **保存期間**: 無期限保存
- **実装状況**: データベーススキーマ定義済み

### FR-043: 更新ステータス管理

- **説明**: 各銘柄の価格更新状況管理
- **ステータス**: SUCCESS、ERROR、PENDING
- **エラー内容**: 詳細なエラーメッセージ保存
- **最終更新日時**: 成功時の更新日時記録
- **実装状況**: データベーススキーマ定義済み

### FR-044: 損益自動再計算

- **説明**: 価格更新時の損益・損益率自動計算
- **計算項目**: 損益、損益率、現在評価額
- **更新範囲**: 価格更新された銘柄のみ
- **整合性**: サマリー情報との整合性保持
- **実装状況**: 基本ロジック実装済み

### FR-045: 米国株の円換算（USD/JPY 日次レート）

- **説明**: 米国株はドル建てで取得・保存し、表示・集計の直前に当日の USD/JPY レートで円換算する（ADR 0005）
- **レート取得**: Yahoo Finance `USDJPY=X` を 1 日 1 回取得し `ExchangeRate` テーブルにキャッシュ
- **換算範囲**: 金額（投資額・評価額・評価損益・予想年間配当）を円換算。単価（平均取得単価・現在価格）は建値通貨（$）のまま表示
- **為替損益**: 取得原価も評価額も当日レートで換算するため損益に含まれない（購入時レートを記録できれば拡張）
- **実装状況**: 実装済み（保有一覧・ダッシュボード・ポートフォリオ・銘柄詳細・取引履歴）。取引履歴では 1 件ごとの取引金額を建値通貨で見せ、合計は円換算してから合算する

### FR-046: セクターの自動入力

- **説明**: 価格更新（`/api/prices/update`・`/api/batch/price-update`）のついでに、銘柄の「市場・セクター」を Yahoo Finance の分類で上書きする（ADR 0017）
- **対象**: 価格更新の対象銘柄のうち、「市場・セクター」が Yahoo の 11 分類でも「ETF」でもない銘柄。既に分類が入っている銘柄には問い合わせない
- **ETF**: Yahoo が分類を返さないため「ETF」と保存する
- **分類が取れないとき**: 今の値を残す。取得に失敗しても価格更新は失敗扱いにしない
- **全銘柄を一度に埋めるには**: ヘッダーの「価格更新」ボタンを 1 回押す。保有株数 0 の銘柄は価格更新の対象外なので埋まらない
- **画面からの入力**: できない。新規銘柄登録には入力欄が無く、編集画面では表示だけ（ADR 0017 の補足）
- **実装状況**: 実装済み（[sector.ts](../../src/lib/sector.ts)）

## 技術仕様

### API設計

- **コード変換**: 日本株の数字コード → .T付きコード自動変換
- **リトライ機能**: 失敗時の自動リトライ（最大3回）
- **タイムアウト**: 1銘柄あたり10秒でタイムアウト
- **並列処理**: 複数銘柄の並列取得（最大10並列）

### データ処理

- **価格フォーマット**: Decimal型での精度保証
- **通貨変換**: 米国株のUSD→JPY変換（必要に応じて）
- **データクレンジング**: 異常値の検出・除外
- **重複排除**: 同一時間帯の重複データ排除

### エラーハンドリング

- **ネットワークエラー**: 接続失敗時のリトライ
- **APIエラー**: レート制限、認証エラーの対応
- **データエラー**: 異常価格データの検証
- **ログ記録**: 全エラーの詳細ログ保存

## 市場セッション管理

### セッション種別

- **MORNING**: 前場（9:00-11:30）
- **AFTERNOON**: 後場（12:30-15:00）
- **AFTER_HOURS**: 時間外取引

### セッション判定

- **判定ロジック**: 取得時刻による自動判定
- **時差対応**: 米国市場の時差考慮
- **休場日対応**: 市場カレンダーとの照合

## 受入条件

### AC-040: 全銘柄の一括更新

- Given: 所有者がアプリを開いている
- When: ヘッダーの「価格更新」ボタンを押す
- Then: 保有中の全銘柄の価格が更新される

### AC-041: 手動更新機能

- Given: ユーザーが手動更新を実行する
- When: 更新ボタンをクリックする
- Then: 選択銘柄の価格が即座に更新される

### AC-042: エラーハンドリング

- Given: 一部銘柄の価格取得が失敗する
- When: バッチ処理を実行する
- Then: 成功した銘柄は更新され、失敗した銘柄はエラーログに記録される

### AC-043: 価格履歴保存

- Given: 価格が更新される
- When: 更新処理が完了する
- Then: 価格履歴テーブルに新しいレコードが追加される

### AC-044: 損益再計算

- Given: 株価が更新される
- When: 価格更新処理が完了する
- Then: 該当銘柄の損益・損益率が自動再計算される

### AC-045: ステータス管理

- Given: 価格更新処理が実行される
- When: 処理が完了する
- Then: 各銘柄の更新ステータスが正しく記録される
