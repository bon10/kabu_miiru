# Simple Commit

## Overview

このスキルは、ステージングされたファイルに対して、シンプルな日本語のコミットメッセージで即座にコミットを実行します。
コミット前にドキュメント（OpenAPI）・権限設定の更新漏れを自動チェックします。

## Workflow

このスキルが実行されたら、以下の手順に従ってください：

### 1. ステージングされた変更を確認

```bash
git status
```

ステージングされている変更を確認します。ステージングされた変更がない場合は、ユーザーに知らせてスキルを終了します。

### 2. 変更内容を確認

```bash
git diff --cached
```

ステージングされた変更の内容を確認し、どのような変更が含まれているかを把握します。

### 3. プリフライトチェック（ドキュメント・権限・ADR の更新漏れ検出）

ステージングされたファイル一覧（`git diff --cached --name-only`）を分析し、以下のチェックを行います。

#### 3-3. ADR 追従チェック

`prisma/schema.prisma`・`src/app/api/**`・`src/lib/**`（換算/集計ロジック等）や、保有・取引・配当・為替換算などドメインに関わる変更が含まれる場合、`adr-check` スキルの手順に従って ADR 追従を検査します。

- 変更が既存 ADR の **Decision** に抵触、または **見直しトリガー** を発火させている場合は、**コミットを止めてユーザーに報告**し、ADR の追従（Status 更新・新規 ADR・トリガー見直し）を確認してから進めます
- ADR が無い領域で新しい設計判断が入っている場合も、新規 ADR の要否を確認します
- 抵触なしなら「ADR 追従の必要なし」と述べて次へ進みます（ADR ディレクトリが無いプロジェクトではスキップ）

### 4. Lint & TypeCheck & Test の実行

ステージングされたファイルの変更を対象に、lint・typecheck・テストを実行します。

```bash
cd stock-portfolio-app && pnpm lint
```

```bash
cd stock-portfolio-app && npx tsc --noEmit
```

```bash
cd stock-portfolio-app && pnpm test
```

- エラー・テスト失敗が発生した場合は、**今回の変更に起因するもののみ**を修正してください（既存の失敗は無視）。
- 修正した場合は、修正ファイルを再度ステージング（`git add`）してください。
- 修正後、再度 lint / typecheck / test を実行して解消されたことを確認してください。
- テストが 1 件も無い領域の変更なら test はスキップ可（テストランナー未導入のプロジェクトでは省略）。

### 5. 簡潔な日本語コミットメッセージを作成

変更内容に基づいて、以下の要件を満たす1行のコミットメッセージを作成します：

- **1行のみ**：複数行は禁止
- **日本語**：すべて日本語で記述
- **簡潔**：変更の本質を端的に表現（目安：10〜30文字程度）
- **AI署名なし**：「🤖 Generated with Claude Code」や「Co-Authored-By」などの署名を含めない

**良い例：**

- `ログイン機能を追加`
- `バグを修正`
- `READMEを更新`
- `依存関係を更新`
- `UIを改善`

**悪い例：**

- `ログイン機能を追加\n\n詳細な説明...` （複数行）
- `Added login feature` （英語）
- `🤖 Generated with Claude Code` （AI署名）

### 6. ユーザーに確認を取る

**必須ステップ：コミットを実行する前に、必ずユーザーに確認を取ってください。**

作成したコミットメッセージをユーザーに提示し、以下の形式で確認を求めます：

```
以下の内容でコミットしますか？

コミットメッセージ: 「〇〇〇」

よろしければ「はい」または「OK」と返信してください。
```

ユーザーが承認した場合のみ、次のステップに進みます。承認されなかった場合は、メッセージの修正を提案するか、スキルを終了します。

### 7. コミットを実行

ユーザーの承認を得た後、シンプルなgitコマンドでコミットを実行します：

```bash
git commit -m "コミットメッセージ"
```

**重要：**

- HEREDOCは使用しない
- `-m`オプションで直接メッセージを渡す
- AI署名やCo-Authored-By行を含めない
- コミット後に`git status`や追加のgitコマンドは実行しない

### 8. ユーザーに完了を報告

コミットが成功したことを簡潔に報告します。例：「コミットしました：〇〇」
